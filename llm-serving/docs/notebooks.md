# Experiment notebooks

The profile notebooks are thin analysis and launch surfaces over the existing YAML profiles and saved runner artifacts. `manifest.json` and `summary.json` remain the canonical record. Opening a notebook and choosing **Run All** only reads local files; remote execution is disabled by default.

## Start Jupyter

From `llm-serving/`, install the analysis extras and open JupyterLab:

```bash
uv sync --extra analysis
uv run --extra analysis jupyter lab notebooks/
```

The analysis extra supplies pandas, Matplotlib, nbformat, nbclient, ipykernel, and JupyterLab. The first notebook is `notebooks/qwen35-0.8b-smoke.ipynb`.

By default, notebooks inspect `llm-serving/output`. Point analysis at another read-only artifact tree before starting Jupyter:

```bash
LLM_SERVING_OUTPUT_ROOT=/path/to/output uv run --extra analysis jupyter lab notebooks/
```

Failed and partial runs stay in the history table. Missing measurements remain blank and chart panels say they are unavailable. If no compatible measured performance or quality data exists, the notebook shows an explicit empty state.

## Launch a deliberate run

The launch section previews the existing harness command. Set a host alias and inventory with `LLM_SERVING_HOST` and `LLM_SERVING_HOST_INVENTORY`; the inventory may be a normal local inventory or a temporary YAML file generated by the local Flash/Runpod driver. Review the command, hypothesis, output root, and any potential GPU cost, then set `RUN_EXPERIMENT = True` in the guarded cell.

The inert Flash preview uses `uv run flash --config runpod.local.yaml plan`, followed by `create --wait` when you deliberately provision. A ready Pod writes `.flash/hosts/<pod-id>.yaml`; the example config uses host alias `runpod-qwen08`. Retrieve the run artifacts and then stop the Pod explicitly with `uv run flash --config runpod.local.yaml stop POD_ID`.

The guarded cell identifies the one newly created run directory and creates `experiment-notes.json` beside its canonical artifacts. It uses exclusive creation and will not replace existing notes or runner artifacts. Edit the hypothesis before launching and fill in observations after inspecting the run.

## Interpretation boundaries

- Baseline deltas are the within-run values already stored by the harness. Do not compare raw values across different hardware or runtime versions without checking the manifests.
- Variability should be shown only when a profile records repeated measurements. The smoke profile currently has one repetition.
- Performance charts use the latest complete measured run by default. Set `LLM_SERVING_RUN_IDS` to a comma-separated list before starting Jupyter to compare explicitly selected runs.
- Quality stays separate from performance. The notebook groups quality rows only when the recorded task settings and named metric match, and it calls out that unrecorded evaluator or prompt-template versions may still differ.
- The smoke profile's 20-example GSM8K task is a pipeline check, not a full benchmark result.

For a clean-kernel verification without JupyterLab, execute the notebook into a temporary location:

```bash
uv run --extra analysis jupyter execute notebooks/qwen35-0.8b-smoke.ipynb
```
